# 🧠 Mental Management Center (MMC) v2.0 — Гуманітарна вебплатформа взаємодії

**Mental Management Center (MMC)** — це архітектурно зріла, криптографічно захищена вебплатформа, розроблена для забезпечення повноцінної асинхронної та синхронної взаємодії між незалежними фахівцями (гуманітарного профілю) та їхніми клієнтами. Проєкт орієнтований на безкомпромісне дотримання приватності, захист конфіденційних даних рефлексії та стабільну роботу в реальному часі.

Платформа є некомерційним, гуманітарним продуктом, не пов'язана з медичними протоколами та базується суворо на етичних стандартах конфіденційності гуманітарної практики. Застосунок повністю розгорнуто та адмініструється на власному автономному Linux-сервері під керуванням `systemd` і Docker із забезпеченням апаратної відмовостійкості (Fault Tolerance інфраструктура на базі ДБЖ та автономного живлення).

---

## 🤖 AI-Human Co-Creation & Чесна розробка

Проєкт MMC є продуктом **гібридної розробки (AI-Assisted Software Engineering)**. Автор проєкту виступав у ролі продуктового архітектора системи, автора бізнес-логіки та унікальних модулів безпеки, а реалізація, точкове закриття багів та оптимізація коду здійснювалися у щільній синергічній взаємодії з LLM-моделями (Google Gemini). Такий підхід демонструє інженерне вміння автора ефективно керувати сучасними інструментами штучного інтелекту для швидкого прототипування, розробки та стабілізації комплексних Enterprise-систем.

## 🛠️ 1. Повний технологічний стек

* **Backend Core:** Java 17, Spring Boot 3.2+ (Web, Security, Data JPA, Validation, WebSocket, Mail, Messaging).
* **Автентифікація & Протоколи безпеки:** Spring Security, **OAuth 2.0 / OIDC (OpenID Connect)** для безшовної авторизації (включаючи Google Login), кастомний заслон захисту тестового оточення (`TestUserProtectionInterceptor`).
* **База даних & Версіонування:** PostgreSQL (Production), Hibernate ORM, **Liquibase** (повна синхронізація схем через 20+ чітких міграційних YAML-файлів).
* **Прикладна криптографія:** JCA (Java Cryptography Architecture), шифрування AES-256-GCM, стиснення GZIP.
* **Мережеві протоколи & Real-Time:** WebSockets (STOMP / SockJS), WebRTC (Jitsi Meet API + RSA-256 JWT).
* **Frontend:** Thymeleaf (SSR), Vanilla JavaScript (ES6+, асинхронні AJAX-модулі, фасади медіаплеєрів).

## 🏗️ 2. Архітектурні модулі та інженерні рішення

### 🔒 Дворівневий захист даних та Прикладна криптографія
* **Криптографія + Компресія:** Текстові записи щоденників стискаються через GZIP (оптимізація дискового простору та зменшення `byte[]` в БД) і шифруються «на льоту» за алгоритмом AES-256-GCM.
* **Деструктуризація файлів (Header Stripping):** При завантаженні приватного медіафайлу система «відриває» його перші 4 КБ (заголовок та метадані файлової структури) і зберігає цей фрагмент у зашифрованому вигляді всередині реляційної БД. Основне «тіло» (хвіст) зберігається на жорсткому диску з SHA-256 дедуплікацією. Файли на диску без ключа бази даних є закритим бінарним шумом.
* **Мультирольова Композиція (Bitwise RBAC):** Права доступу закодовані через степені двійки в одному цілочисельному полі `rolesMask` (Enum `RoleBit`: `GUEST`, `READER`, `CLIENT`, `THERAPIST`, `ADMIN`, `TEST`). Це дозволяє володіти кількома ролями одночасно (наприклад, ADMIN + THERAPIST).

### 🏥 Підсистема терапевтичної практики (Therapy Workspace)
* **Договори терапії (`TherapyAssignment`):** Модуль формалізації стосунків «Клієнт–Терапевт» із контролем статусів (`PENDING`, `ACTIVE`, `FINISHED`).
* **Календар & Інтерактивні сесії (`TherapySession`):** Система планування зустрічей, обсягу консультацій, обробки скасувань та зв'язку з персональним календарем.
* **Екстрений SOS-сигнал (`SosRequest`):** Модуль запрошення клієнтом адміністратора до терапевтичної кімнати (`TherapyRoom`) у разі порушення терапевтом етичних, професійних тощо стандартів співпраці на терапевтичній стіні (`SharedWall`).
* **Клієнтські нотатки (`TherapyNote`):** Ізольований простір занотовування ходу терапевтичних сесій з можливістю доступу авторів.

### 🎓 Модерація фахівців та Конструктор портфоліо
* **Верифікація дипломів (`SpecialistApplication`):** Подача заявок фахівців із зазначенням рівня освіти, серії/номеру диплома та перевіркою адміністратором.
* **Портфоліо психотерапевта (`TherapistPortfolio`):** Деталізований конструктор профілю з підходами (КПТ, Гештальт тощо), запитами, етичними принципами та чітким розмежуванням медичної і немедичної практики.

### 📡 Мережевий телекомунікаційний хаб & Real-Time
* **Повнодуплексний чат спільноти:** Побудований на базі Spring WebSockets та протоколу STOMP з розділенням на публічні та приватні канали. Витягування повідомлень реалізовано порціями через `Spring Data Slice` (нескінченний скрол).
* **Захищений відеозв'язок (WebRTC):** Інтегровано сервіс Jitsi Meet з серверною генерацією тимчасових JWT-токенів, підписаних асиметричним алгоритмом RSA-256.

### 💬 Спільнота, Публічні стіни та Двигун реакцій
* **Асинхронний двигун емоцій (`Reaction`):** Система з 5 типів реакцій (🫂, 💛, 💡, 🙏, 👍) для статей, коментарів, чатів та публічних дописів з подійною моделлю сповіщень.
* **Модерація та скарги (`Report`):** Дворівневий журнал скарг та оскаржень контенту з можливістю задоволення/відхилення тикету адміністратором.
* **Публічна стіна фахівця (`PublicPost`):** Авторські дописи терапевтів з можливістю обговорення спільнотою та автоматичним форматуванням медіапосилань.

### 📐 Математична дизайн-система та колірний двигун
* **Відмова від пікселів (`px`):** Верстка побудована на відносних одиницях (`rem`, `vh`), квантовій сітці та динамічних обчисленнях `calc()`.
* **Градієнтний спектральний колірний двигун:** Індивідуальне налаштування інтерфейсу через HSL-токени з підтримкою математичної інверсії світлості для нічного режиму.

## 🗄️ 3. Управління даними та Версіонування (Liquibase)

Структура PostgreSQL перебуває під повним контролем Liquibase. Проєкт відмовився від неконтрольованої автоматичної генерації схем Hibernate (`ddl-auto: validate`), перейшовши на серію послідовних YAML-змін (changelogs 001–023). Усі міграції оснащені блоками `preConditions` (`MARK_RAN`), що гарантує безпечний запуск як на чистих екземплярах, так і на існуючих продакшен-базах.

## 💻 5. Системне адміністрування та Production

Проєкт розгорнуто на власному фізичному обладнанні під керуванням OS Linux:
* **Systemd Service:** Застосунок працює як автономна служба `mmc.service` з автоперезапуском.
* **Docker Infrastructure:** PostgreSQL працює в ізольованому контейнері `mmc-postgres`.
* **Резервне копіювання:** Щоночі о 3:00 скрипт `backup_mmc.sh` виконує інкрементне бекапування медіафайлів та SQL-дампи БД.

### 🛡️ Обмеження безпеки та захист демо-середовища

Для забезпечення цілісності демонстраційного стенду та захисту реальних користувачів у системі реалізовано декілька рівнів ізоляції:

* **Блокування модифікуючих запитів (`TestUserProtectionInterceptor`):**
  Усі тестові облікові записи мають спеціальний прапор доступу (`RoleBit.TEST`). Перехоплювач на рівні Spring MVC блокує будь-які спроби мутації даних (HTTP-методи `POST`, `PUT`, `DELETE`, `PATCH`) для критичних системних ресурсів, запобігаючи спотворенню публічного демонстраційного середовища сторонніми відвідувачами.
* **Строга ізоляція приватних даних:**
  Тестові користувачі функціонують у повністю відокремленому просторі. Жодні персональні рефлексії, нотатки чи листування реальних клієнтів платформи не доступні для перегляду або взаємодії з публічних тестових профілів.
* **Авторизація через Google OAuth 2.0 / OIDC:**
  Шлюз входження через Google призначений для авторизації реальних користувачів проєкту. Тестові облікові записи є локально зафіксованими сутностями бази даних і функціонують виключно через стандартну форму аутентифікації на базі логіна та пароля.
